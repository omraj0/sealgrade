# Contributing

## Set up

```bash
python -m venv .venv && . .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
```

Docker must be running for the integration tests and for `sealgrade matrix`.

## Checks (all must pass)

```bash
ruff check . && ruff format --check .
mypy
python tools/gen_cases.py --check      # task cases are generated and committed
python tools/gen_docs.py --check       # CORPUS.md and AUDIT_RULES.md are generated from the code
pytest -m "not docker"                 # fast, no Docker needed
pytest -m docker                       # real containers: controls and every documented attack outcome
```

To keep a local Docker run short, narrow the task sets:

```bash
SEALGRADE_MATRIX_TASKS=py-slugify SEALGRADE_CONTROL_TASKS=py-slugify pytest -m docker
```

## Adding an attack

1. Create `corpus/<attack-id>/` (lower-case words joined by hyphens).
2. Write `attack.toml`:

   ```toml
   [attack]
   id = "my-attack"
   title = "One line"
   summary = "What it does and why it should work on a weak harness."
   classes = ["V3"]                      # from docs/TAXONOMY.md
   patterns = ["Short name of the pattern"]
   kind = "exploit"                      # or "probe": a boundary test that must be blocked everywhere
   requires = []                         # e.g. ["no-raising-cases"] to skip tasks it cannot apply to
   agent_script = "agent.sh"             # optional: what a hostile agent runs in its sandbox
   repeat = 1                            # >1 for timing-dependent attacks

   [files]                               # files left in the agent's working directory
   "solution.py" = "../_common/stub_solution.py"   # a wrong stub, so only the exploit can pass
   "conftest.py" = "payload/conftest.py"

   [expected]                            # what you claim happens, per tier
   t0 = "exploit"
   t1 = "blocked"
   t2 = "blocked"
   t3 = "blocked"
   ```

3. Rules for a valid attack:
   - It must **not** solve the task. The success rule is "verdict says pass". Ship a wrong stub
     (`../_common/stub_solution.py`) so the exploit is the only way to a pass.
   - Every exploit must beat tier T0; a probe must be blocked on every tier.
   - You must state a claim for **every** tier (`t0` to `t3`). The strict tier must block it.
   - Shell payloads use Unix line endings.
   - Keep it small and readable; the payload is the documentation.
4. Run `sealgrade matrix --attacks my-attack --no-controls --check --tiers t0,t1,t2,t3`. If your claim and
   the measurement disagree, fix the claim or the attack; do not loosen the check. A `PARTIAL` result means the
   attack is flaky, which is also a bug (see `tools/flake_check.py`).
5. Run `python tools/gen_docs.py` so `docs/CORPUS.md` includes it.

## Adding a task

A task is a folder under `tasks/` with `task.toml`, `instruction.md`, `cases.jsonl` (generated by
`tools/gen_cases.py` from the oracle, seeded and deterministic), `oracle/` and `near_miss/`. Tasks must be
written from scratch and use only the standard library. Add a generator function to `tools/gen_cases.py`.

## Adding an auditor rule

Add a function to `src/sealgrade/audit/rules.py`, register it in `RULES` with a flaw class and a remedy, and add
a **planted-flaw fixture** to `tests/audit_fixtures.py` (a clean task mutated to contain exactly that flaw).
The test suite requires every static rule to have one, and requires the clean task to produce no findings.

## Releasing

Tag `vX.Y.Z`. The `Release` workflow builds the sdist and wheel and creates a GitHub release. To publish to
PyPI, configure a [trusted publisher](https://docs.pypi.org/trusted-publishers/) for this repository and set the
repository variable `PYPI_PUBLISH` to `true`.
